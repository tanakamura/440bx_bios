# 440BX Notes

このファイルには Intel 440BX の仕様メモを蓄積する。

## Current assumptions

- Reset execution starts from the ROM window at `f000:fff0`.
- The visible ROM window at reset is the top `64 KiB` of the `256 KiB` ROM image.
- PCI/chipset investigation should be done with CPU/FSB clocking set to the CPU-appropriate condition, not the slowest setting.

## PAM / shadow RAM

- 440BX host bridge PCI config registers `0x59-0x5f` are the PAM registers.
- `PAM0` (`0x59`) controls the system BIOS `0xf0000-0xfffff` shadow window. Setting bits `5:4` to `11b` enables reads and writes to DRAM for that window.
- `PAM1-PAM6` (`0x5a-0x5f`) control `0xc0000-0xeffff` in 16 KiB halves. Writing `0x33` enables reads and writes to DRAM for both halves of each register.
- After DRAM init, a small loader running from DRAM switches `0xe0000-0xfffff` to shadow DRAM, expands `BIOS.elf` there, and jumps to its 32-bit entry at `0xe0000`.
- The runtime can switch `0xc0000-0xdffff` to shadow DRAM for option ROM use, but must not clear `0xe0000-0xfffff` because that contains the active BIOS runtime and thunk.
- `0xc0000-0xdffff` is reserved for option ROM use, especially VGA ROM. `0xe0000-0xfffff` is reserved for the BIOS runtime.
- A VGA option ROM placed at `0xc0000` is not fully initialized just by copying it. After PCI BARs and bridge VGA forwarding are configured, the BIOS can call the option ROM init entry at `C000:0003` in real mode. Do this after installing BIOS service thunks, because the option ROM may use legacy BIOS interrupts during initialization.

## Observed behavior

- `00:00.0` vendor/device probing has produced `8086/7190` under stable clocking.
- With incorrect or excessively slow clocking, ROM execution can still partially work while PCI / chipset probing becomes misleading or unstable.
- During SDRAM bring-up, once `DRB` starts decoding low memory as DRAM, a CAR stack placed in the first MiB overlaps the DRAM decode window. Special SDRAM command sequences (`NOP` / `PRECHARGE` / `CBR` / `MRS`) should therefore run without stack accesses.
- On this board, the SDRAM command sequence needed a much longer post-NOP delay than the earlier tiny test loop. With the longer delay plus a stackless command block, SDRAM init and basic read/write passed.
- A confirmed run with the current DIMM at SPD `0x52` completed SDRAM init and passed read/write tests at `0x00100000` and `0x00100004`.
- Bootblock / BIOS payload reads should use the top ROM alias (`0xfffc0000` for the current 256 KiB image), not the low `0x000e0000` window. The low E-region alias was not reliable enough for blob/service reads on real hardware.
- Real hardware ROM reads can return occasional bad bytes even when the external ROM uploader readback compares OK. Payload blobs therefore use CRC-protected independent blocks, and the runtime blob copy path reads each ROM byte multiple times before accepting it.
- Pentium II / P6 variable MTRR masks need the high dword mask bits filled for the 36-bit physical address width. For the low WB DRAM range, `IA32_MTRR_PHYSMASK0.edx` should be `0x0000000f`; leaving it zero makes Linux report an incorrect BIOS MTRR mask and fix it.

## PCI resource assignment

- The 440BX AGP device appears as a PCI-to-PCI bridge at `00:01.0`; devices below it are on secondary bus `01`.
- Endpoint BAR allocation is not enough. The BIOS must assign bridge bus numbers and bridge I/O / memory windows before handing control to Linux, otherwise Linux reports failures such as `bridge window [mem size 0x01100000]: can't assign; no space` and AGP VGA BARs remain unusable.
- The BIOS allocator traverses the PCI tree recursively: measure endpoint BAR sizes with the normal all-ones BAR probe, accumulate child-bus requirements, round bridge I/O windows to `4 KiB`, round memory/prefetch windows to `1 MiB`, then assign parent windows and child BARs in a second pass.
- Low RAM is not used for PCI MMIO. The root PCI memory allocator starts at `max(align16M(total DRAM), 0x04000000)`.
