# 440BX Notes

このファイルには Intel 440BX の仕様メモを蓄積する。

## Current assumptions

- Reset execution starts from the ROM window at `f000:fff0`.
- The visible ROM window at reset is the top `64 KiB` of the `256 KiB` ROM image.
- PCI/chipset investigation should be done with CPU/FSB clocking set to the CPU-appropriate condition, not the slowest setting.

## Observed behavior

- `00:00.0` vendor/device probing has produced `8086/7190` under stable clocking.
- With incorrect or excessively slow clocking, ROM execution can still partially work while PCI / chipset probing becomes misleading or unstable.
- During SDRAM bring-up, once `DRB` starts decoding low memory as DRAM, a CAR stack placed in the first MiB overlaps the DRAM decode window. Special SDRAM command sequences (`NOP` / `PRECHARGE` / `CBR` / `MRS`) should therefore run without stack accesses.
- On this board, the SDRAM command sequence needed a much longer post-NOP delay than the earlier tiny test loop. With the longer delay plus a stackless command block, SDRAM init and basic read/write passed.
- A confirmed run with the current DIMM at SPD `0x52` completed SDRAM init and passed read/write tests at `0x00100000` and `0x00100004`.
- Bootblock / BIOS payload reads should use the top ROM alias (`0xfffc0000` for the current 256 KiB image), not the low `0x000e0000` window. The low E-region alias was not reliable enough for blob/service reads on real hardware.
- Real hardware ROM reads can return occasional bad bytes even when the external ROM uploader readback compares OK. Payload blobs therefore use CRC-protected independent blocks, and the runtime blob copy path reads each ROM byte multiple times before accepting it.
